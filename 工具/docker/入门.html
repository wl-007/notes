Docker 入门 ​

1. Docker 是什么 ​

Docker 是一套容器化工具，用来把应用和它运行所需的环境一起打包，然后在不同机器上以更一致的方式运行。

如果你只记一句话，可以先记这个：

Docker 解决的是“我这能跑，你那也得能跑”的环境一致性问题。

2. 先理解 4 个核心概念 ​

镜像 ​

镜像可以理解成“应用运行模板”。

它包含：

  • 应用代码
  • 运行时环境
  • 依赖
  • 启动命令

镜像本身不运行，它更像一个只读模板。

容器 ​

容器是镜像启动后的运行实例。

同一个镜像可以启动多个容器。

Dockerfile ​

Dockerfile 是构建镜像的说明书。

你告诉 Docker：

  • 以哪个基础镜像开始
  • 拷贝哪些文件
  • 安装哪些依赖
  • 用什么命令启动

然后 Docker 按顺序构建出镜像。

仓库 ​

仓库用来存镜像。

最常见的是 Docker Hub。

3. Docker Engine、Docker Desktop、Docker Compose 是什么关系 ​

按照 Docker 官方文档的定义：

  • Docker Engine：真正创建和运行容器的核心技术
  • Docker CLI：你在命令行里敲的 docker 命令
  • Docker Desktop：桌面端开发环境，通常包含 Engine、CLI、Compose 等能力
  • Docker Compose：用一个 compose.yaml 管理多容器应用

对大多数本地开发者来说：

  • macOS / Windows 常见是装 Docker Desktop
  • Linux 常见是直接装 Docker Engine

4. 安装后先验证什么 ​

安装完成后，先确认版本：

bash
docker --version
docker compose version

再跑官方常见的测试思路：

bash
docker run hello-world

如果能正常输出欢迎信息，说明 Docker 基本可用。

5. 最常用命令先记这几个 ​

查看本地镜像：

bash
docker images

查看运行中的容器：

bash
docker ps

查看所有容器：

bash
docker ps -a

拉取镜像：

bash
docker pull nginx

启动一个容器：

bash
docker run -d --name my-nginx -p 8080:80 nginx

这里的含义：

  • -d：后台运行
  • --name：给容器起名字
  • -p 8080:80：把宿主机 8080 端口映射到容器 80 端口

停止容器：

bash
docker stop my-nginx

启动已停止容器：

bash
docker start my-nginx

删除容器：

bash
docker rm my-nginx

查看日志：

bash
docker logs my-nginx

进入容器：

bash
docker exec -it my-nginx sh

6. 镜像和容器的关系 ​

一个很常见的误区是把镜像和容器混成一个东西。

可以这样理解：

  • 镜像是“类”
  • 容器是“对象实例”

或者更接地气一点：

  • 镜像像安装包
  • 容器像运行起来的程序

7. 自己构建一个镜像 ​

下面是一个最小 Node 示例：

dockerfile
FROM node:20-alpine

WORKDIR /app

COPY package*.json ./
RUN npm install

COPY . .

EXPOSE 3000

CMD ["npm", "run", "start"]

构建镜像：

bash
docker build -t my-node-app .

运行镜像：

bash
docker run -d --name my-node-app -p 3000:3000 my-node-app

8. Dockerfile 里最常见的指令 ​

根据 Docker 官方 Dockerfile reference，入门阶段最常见的是这些：

  • FROM：指定基础镜像
  • WORKDIR：设置工作目录
  • COPY：拷贝文件到镜像
  • RUN：构建时执行命令
  • EXPOSE：声明容器使用的端口
  • CMD：默认启动命令
  • ENV：设置环境变量

一个简单理解 ​

  • RUN 是构建镜像时执行
  • CMD 是容器启动时执行

这两个经常被刚学 Docker 的人混淆。

9. 数据持久化：卷和挂载 ​

容器本身是临时的，如果容器删了，里面的数据往往也会跟着没。

这时就需要持久化。

Docker 官方更推荐用 volume 来持久化数据。

volume ​

bash
docker volume create mysql-data

运行时挂载：

bash
docker run -d \
  --name my-mysql \
  -e MYSQL_ROOT_PASSWORD=123456 \
  -v mysql-data:/var/lib/mysql \
  mysql:8

Docker 官方文档里提到，volume 是持久化容器数据的首选方式。

bind mount ​

如果你希望容器直接使用宿主机某个目录，也可以绑定挂载：

bash
docker run -d \
  --name my-nginx \
  -p 8080:80 \
  -v $(pwd)/html:/usr/share/nginx/html \
  nginx

这个更适合：

  • 本地开发
  • 需要直接改宿主机文件并即时映射进容器

10. 网络怎么理解 ​

Docker 容器之间可以通过网络互相通信。

入门阶段先知道两点就够：

  • 单容器对外访问，通常靠端口映射 -p
  • 多容器互相通信，通常靠 Docker 网络

创建一个网络：

bash
docker network create app-net

把容器放进这个网络：

bash
docker run -d --name redis --network app-net redis
docker run -d --name web --network app-net my-node-app

这样 web 容器里通常就可以直接通过 redis 这个服务名访问 Redis。

11. 清理命令也很重要 ​

Docker 用久了以后，本地很容易堆很多没用的资源。

常见清理命令：

删除没用的容器：

bash
docker container prune

删除没用的镜像：

bash
docker image prune

删除没用的卷：

bash
docker volume prune

清理未使用资源：

bash
docker system prune

这类命令执行前要先看清楚，避免把还需要的资源删掉。

12. 一条适合开发者的 Docker 入门路径 ​

如果你是前端或全栈开发，可以按这个顺序学：

  1. 安装并跑通 hello-world
  2. 拉一个 nginx 镜像跑起来
  3. 理解 docker ps、docker logs、docker exec
  4. 自己写一个最小 Dockerfile
  5. 用 docker build 构建自己的镜像
  6. 理解 volume 和 bind mount
  7. 再进入 Compose

13. 常见误区 ​

误区 1：Docker 不是虚拟机 ​

容器比传统虚拟机更轻量，容器共享宿主机内核。

误区 2：容器删了数据一定还在 ​

不一定。没有做 volume 或挂载时，数据可能直接丢。

误区 3：只会 docker run 就够了 ​

真到项目里，通常还需要：

  • Dockerfile
  • 卷
  • 网络
  • Compose

14. 本篇小结 ​

这一篇最重要的不是把命令背全，而是先把下面几件事搞清楚：

  • 镜像和容器的区别
  • Dockerfile 是干什么的
  • 端口映射怎么用
  • 为什么需要 volume
  • 为什么多容器项目通常要上 Compose
