# APIRouter 与路由分级

当前部门详情接口的完整地址由三层组成：

```text
/apiCommon + /test + /dept + /detail/{dept_id}
全局前缀      模块组    业务模块   路径操作
```

```bash
curl "http://127.0.0.1:8801/apiCommon/test/dept/detail/1"
```

```json
{"message": "dept detail", "id": 1}
```

## 从一个路由对象开始

```python
from fastapi import APIRouter

DeptRouter = APIRouter(prefix="/dept", tags=["test/dept"])


@DeptRouter.get("/detail/{dept_id}", summary="查询部门详情")
async def get_dept_detail(dept_id: int):
    return {"message": "dept detail", "id": dept_id}
```

`APIRouter` 用于组织路径操作，只有被包含进应用后才会对外提供接口。

| 配置 | 作用 |
| --- | --- |
| `prefix` | 为这组路由添加路径前缀 |
| `tags` | 在接口文档中分组，不改变 URL |
| `summary` | 单个操作的文档摘要 |
| `dependencies` | 为一组操作统一执行依赖 |
| `responses` | 补充响应文档，单独配置它不会实现错误处理 |

在路由级声明依赖适合统一执行鉴权等检查；如果路由函数需要依赖返回值，仍应通过函数参数注入。

## 项目如何逐层组合

`backend/app/api/test/__init__.py`：

```python
from fastapi import APIRouter

from .dept.controller import DeptRouter
from .log.controller import LogRouter
from .user.controller import UserRouter

test_router = APIRouter(prefix="/test")
test_router.include_router(DeptRouter)
test_router.include_router(LogRouter)
test_router.include_router(UserRouter)
```

`backend/app/init_app.py` 再把模块组接入应用：

```python
def register_routers(app: FastAPI, settings: Settings) -> None:
    from app.api.common import common_router
    from app.api.sys import sys_router
    from app.api.test import test_router

    app.include_router(common_router, prefix=settings.API_PREFIX)
    app.include_router(sys_router, prefix=settings.API_PREFIX)
    app.include_router(test_router, prefix=settings.API_PREFIX)
```

`sys` 是后续提交新增的模块。注册顺序来自实际调用，框架不会因为目录叫 `api` 就自动发现其中所有路由。

## 文件结构为什么这样安排

```text
backend/
  main.py
  app/
    init_app.py
    api/
      test/
        __init__.py
        dept/controller.py
        log/controller.py
        user/
          controller.py
          schema.py
          service.py
          crud.py
          model.py
      sys/user/
      common/file/controller.py
```

路由只负责 HTTP 边界，业务规则放在 Service，数据库表达式放在 CRUD。早期的部门、日志模块只是路由演示，不必为了目录整齐就补出空的服务层。

`__init__.py` 在本项目中标识普通 Python 包，也可作为路由聚合入口。Python 还支持命名空间包，因此“所有 Python 包都必须有它”不是普遍规则。

## 静态路径先于动态路径

```python
@UserRouter.get("/me")
async def read_me():
    ...


@UserRouter.get("/{user_id}")
async def read_user(user_id: int):
    ...
```

路由按注册顺序匹配。若把 `/{user_id}` 放前面，请求 `/me` 可能先匹配动态路由，然后因整数校验失败返回 422，并不会自动继续尝试后面的 `/me`。

当前系统用户将 `/me`、`/popular` 放在 `/{user_id}` 前面。不同 HTTP 方法可以共用路径；相同方法和路径重复注册会让后面的处理函数不可达，详见参数章节。

## 尾部斜杠也是路径的一部分

`/items` 与 `/items/` 可以被分别声明。默认的斜杠重定向用于目标形式未被匹配的情况，不能据此认为两个地址始终是同一个接口。

项目中分页用户接口声明为 `GET ""`，完整路径是 `/apiCommon/sys/user`；文档和请求示例优先使用它，减少额外重定向。

参考：[大型应用与多文件](https://fastapi.tiangolo.com/tutorial/bigger-applications/)、[路径顺序](https://fastapi.tiangolo.com/tutorial/path-params/#order-matters)。
