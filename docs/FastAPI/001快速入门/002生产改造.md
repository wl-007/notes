# typer

它也是一个用于运行脚本的命令行工具，可自动将其转换为 CLI 应用程序。

主要特性包括：

- 编写直观 ：出色的编辑器支持。处处都能自动补全 。减少调试时间。设计上易于使用和学习。减少阅读文档的时间。
- 易于使用 ：对最终用户来说很容易使用。自动帮助，以及所有 shell 的自动补全。
- 简短 ：最小化代码重复。每个参数声明具有多种功能。更少的 bug。
- 从简单开始 ：最简单的示例只需向你的应用添加 2 行代码：1 个导入，1 个函数调用 。
- 大规模扩展 ：随心所欲地增加复杂度，创建任意复杂的命令树和子命令组，并附带选项和参数。
- 运行脚本 ：Typer 包含一个 typer 命令/程序，你可以用它来运行脚本，自动将其转换为 CLI，即使脚本内部并未使用 Typer。


## 最简示例

```py
import typer

app = typer.Typer()


@app.command()
def hello(name: str):
    print(f"Hello {name}")


@app.command()
def goodbye(name: str, formal: bool = False):
    if formal:
        print(f"Goodbye Ms. {name}. Have a good day.")
    else:
        print(f"Bye {name}!")


if __name__ == "__main__":
    app()

```

这样将会：

1.  显式创建一个 typer.Typer 应用。
2.   之前的 typer.run 实际上为你隐式创建了一个。
3.  使用 @app.command() 添加两个子命令。
4.  像调用函数一样执行 app() 本身。


执行命令

```shell
uv run python main.py hello Camila
uv run python main.py goodbye Camila
```

# 设置和环境变量

在许多情况下，你的应用可能需要一些外部设置或配置，例如密钥、数据库凭据、电子邮件服务的凭据等。

这些设置中的大多数是可变的（可能会改变），例如数据库 URL。并且很多可能是敏感的，比如密钥。

在 fastapi 中 我们使用 Pydantic 提供的Settings 来处理来自环境变量的这些设置

## 安装 pydantic-settings

```bash
uv add pydantic-settings
```

## 创建 Settings 对象

```py
from fastapi import FastAPI
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    app_name: str = "Awesome API"
    admin_email: str
    items_per_user: int = 50

settings = Settings()
app = FastAPI()


@app.get("/info")
async def info():
    return {
        "app_name": settings.app_name,
        "admin_email": settings.admin_email,
        "items_per_user": settings.items_per_user,
    }
```

```py{8}
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    app_name: str = "Awesome API"
    admin_email: str
    items_per_user: int = 50

    model_config = SettingsConfigDict(env_file=".env")
```

## 使用 lru_cache 仅创建一次 Settings

从磁盘读取文件通常是一个代价较高（缓慢）的操作，所以你可能希望只在第一次读取，然后复用同一个设置对象，而不是为每个请求都重新读取。

但是，每次我们执行`Settings()`都会创建一个新的 Settings 对象，并且在创建时会再次读取 .env 文件。

如果依赖项函数是这样的：

```py
def get_settings():
    return Settings()
```
我们就会为每个请求创建该对象，并为每个请求读取 .env 文件。 ⚠️

但由于我们在顶部使用了 @lru_cache 装饰器，Settings 对象只会在第一次调用时创建一次。


```py
from functools import lru_cache
from typing import Annotated

from fastapi import Depends, FastAPI

from . import config

app = FastAPI()


@lru_cache
def get_settings():
    return config.Settings()


@app.get("/info")
async def info(settings: Annotated[config.Settings, Depends(get_settings)]):
    return {
        "app_name": settings.app_name,
        "admin_email": settings.admin_email,
        "items_per_user": settings.items_per_user,
    }
```

# uvicorn

Uvicorn 是一个用于 Python 的 ASGI Web 服务器实现。使用 ASGI 规范与应用程序进行交互。

应用程序应暴露一个异步可调用对象，该对象接受三个参数：

- scope - 一个包含传入连接信息的字典。
- receive - 用于从服务器接收传入消息的通道。
- send - 用于向服务器发送传出消息的通道。

## ASGI

ASGI（ 异步服务器网关接口 ）是 WSGI 的精神继承者，旨在为支持异步的 Python Web 服务器、框架和应用程序之间提供标准接口。

WSGI 为同步 Python 应用提供了标准，而 ASGI 为异步和同步应用都提供了标准，并包含 WSGI 向后兼容实现以及多种服务器和应用程序框架。

## 代码解读

```py
uvicorn.run(
    # 以 "模块:工厂函数" 的字符串形式传入，uvicorn 内部会先导入 main 模块
    # 再调用 create_app() 得到 ASGI 应用实例。
    app="main:create_app",
    host=settings.SERVER_HOST,
    port=settings.SERVER_PORT,
    # 热重载：文件变更时自动重启进程。
    reload=(env is EnvironmentEnum.DEV),
    # 日志级别固定为 info，输出请求访问日志和启动信息。
    log_level="info",
    # 声明 app 参数是工厂函数而非应用实例。
    # 没有这个标记，uvicorn 会把 "main:create_app" 当作应用对象直接使用，
    # 而不是调用它，导致拿到的是函数本身而非 ASGI 应用。
    factory=True,
)
```
