## Typer：把函数变成命令

```python
import typer

cli = typer.Typer()


@cli.command()
def hello(name: str):
    print(f"Hello {name}")


if __name__ == "__main__":
    cli()
```

Typer 将类型提示用于解析命令行参数。当前 `main.py` 还定义了 `run`、`revision`、`upgrade`；用帮助命令查看实际选项：

```bash
uv run main.py --help
uv run main.py run --help
```

`backend/package.json` 只是为这些 Python 命令提供快捷入口，例如 `pnpm dev`。不用 Node 时可以直接执行原命令。

## 为什么先选环境，再导入配置

项目中的关键步骤可以缩写为：

```python
import os

from app.common.enums import EnvironmentEnum


def load_settings(env: EnvironmentEnum):
    os.environ["ENVIRONMENT"] = env.value
    from app.config.setting import settings

    return settings
```

配置文件路径在 `setting.py` 首次导入时计算：

```python
model_config = SettingsConfigDict(
    env_file=ENV_DIR / f".env.{os.getenv('ENVIRONMENT')}",
    env_file_encoding="utf-8",
    extra="ignore",
    case_sensitive=True,
)
```

因此，先导入 `settings` 再修改 `ENVIRONMENT`，不会自动重建配置对象。直接运行 `uvicorn main:create_app --factory` 时，也需要事先提供 `ENVIRONMENT=dev`；项目的 Typer 入口已经处理了顺序。

`ENV_DIR` 来自 `path_conf.py`，以 `backend` 为基准，不依赖终端当前目录拼接配置路径。

## Pydantic Settings：外部配置的边界

独立示例：

```python
from functools import lru_cache

from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", extra="ignore")

    APP_NAME: str = "Awesome API"
    SERVER_PORT: int = 8801
    JWT_SECRET_KEY: str


@lru_cache(maxsize=1)
def get_settings() -> Settings:
    return Settings()
```

`BaseSettings` 从环境变量、dotenv 等来源加载并校验配置。以上常规来源中，显式初始化参数优先于系统环境变量，系统环境变量优先于 dotenv，未提供的字段再使用默认值。

项目采用大写字段并设置 `case_sensitive=True`。`extra="ignore"` 表示忽略 dotenv 中未声明的配置项，不表示可以忽略字段类型错误。

本地配置形态如下，密码和密钥用自己的环境变量提供：

```dotenv
ENVIRONMENT=dev
SERVER_HOST=0.0.0.0
SERVER_PORT=8801
API_PREFIX=/apiCommon
DATABASE_HOST=127.0.0.1
DATABASE_PORT=3306
DATABASE_NAME=fastapi_template
REDIS_ENABLE=true
```

不要把实际密钥复制进笔记。`JWT_SECRET_KEY` 的长度校验由认证模块执行，未配置或少于 32 字节时相关流程返回 503。

## 缓存配置对象的意义

`@lru_cache(maxsize=1)` 让每个进程复用同一个配置对象，避免多次读取 dotenv。它不是 Redis 缓存，也不会跨进程共享。

修改 `.env` 后通常需要重启服务；只清理函数缓存还不够，因为模块级 `settings = get_settings()` 已经保存了旧引用。测试可以覆盖具体依赖或配置，但不要把生产环境切换实现成运行中随意改全局变量。

## 应用工厂与 Uvicorn

当前 `create_app()` 的职责是组装应用：

```python
from fastapi import FastAPI

from app.config.setting import settings
from app.init_app import (
    lifespan,
    register_exceptions,
    register_middlewares,
    register_routers,
)


def create_app() -> FastAPI:
    app = FastAPI(lifespan=lifespan)
    register_routers(app, settings)
    register_exceptions(app)
    register_middlewares(app)
    return app
```

这个片段展示组装结构；在项目入口中，相关导入放在函数内部，以配合先设置环境的要求。

Uvicorn 使用字符串定位工厂函数：

```python
uvicorn.run(
    app="main:create_app",
    host=settings.SERVER_HOST,
    port=settings.SERVER_PORT,
    reload=(env is EnvironmentEnum.DEV),
    log_level=False,
    factory=True,
)
```

- `factory=True` 表示导入后调用函数取得应用实例。
- `reload` 用于开发时重启进程，生产环境关闭。
- `host="0.0.0.0"` 表示监听所有网卡，浏览器访问时用实际 IP 或 `127.0.0.1`。
- 当前 `log_level=False` 是源码现状，不能据此认为 Uvicorn 日志已经接入 Loguru。
- `reload` 与多 worker 部署是不同机制，不应同时启用。

生命周期负责启动与释放外部资源，具体见 [热门用户缓存实现](../006Redis缓存/002热门用户缓存实现.md)。
