# 请求头、响应头与 Cookie

对应提交：`de407fd`（2026-10-09，参数解析情况）。

项目中的 `/setHeader` 同时演示两件事：从请求头读取数据，以及在响应中写入头部。二者方向不同。

## 使用 Header 读取请求头

```python
from typing import Annotated

from fastapi import APIRouter, Header, Response
from pydantic import BaseModel

LogRouter = APIRouter(prefix="/log")


class CommonHeaders(BaseModel):
    host: str
    save_data: bool | None = None
    if_modified_since: str | None = None
    traceparent: str | None = None


@LogRouter.get("/setHeader")
async def set_header(
    response: Response,
    headers: Annotated[CommonHeaders, Header()],
):
    response.headers["Cache-Control"] = "no-store"
    response.headers["X-Request-Id"] = "abc-123"
    response.headers["Content-Language"] = "zh-CN"
    return headers
```

```bash
curl -i "http://127.0.0.1:8801/apiCommon/test/log/setHeader" \
  -H "save-data: true" \
  -H "if-modified-since: Wed, 21 Oct 2026 07:28:00 GMT" \
  -H "traceparent: demo-trace"
```

`Host` 通常由 HTTP 客户端提供。Header 名不区分大小写；FastAPI 默认将 Python 字段中的下划线转换为连字符，所以 `save_data` 对应 `save-data`。

`traceparent` 在此仅作为字符串接收，代码并未验证追踪协议格式；固定的 `abc-123` 也只是示例值，项目没有据此实现真实请求 ID 生成。

## 常用头部应该放在哪里

| 头部 | 方向 | 作用 |
| --- | --- | --- |
| `Content-Type` | 请求 / 响应 | 描述当前消息体的媒体类型 |
| `Accept` | 请求 | 客户端期望的响应媒体类型 |
| `Authorization` | 请求 | 例如 `Bearer <token>` |
| `Origin` | 请求 | 浏览器请求的源，用于 CORS |
| `Cookie` | 请求 | 浏览器发送已保存的 Cookie |
| `Set-Cookie` | 响应 | 服务端设置 Cookie，可出现多次 |
| `Cache-Control` | 响应中常用 | HTTP 缓存控制 |
| `ETag` / `If-None-Match` | 响应 / 请求 | 资源版本与条件请求 |
| `WWW-Authenticate` | 响应 | 通知客户端认证方案 |
| `Access-Control-Expose-Headers` | 响应 | 允许跨域 JavaScript 读取指定响应头 |

JSON、表单和文件上传都可能携带 `Content-Type`，不能用 GET/POST 名字推断媒体类型。项目的注册用 JSON，登录用 `application/x-www-form-urlencoded`。

`Origin` 只包含协议、主机和端口；`Referer` 可以包含路径，但受浏览器策略影响，并非总有完整 URL。代理转发的 `X-Forwarded-For` 只有在可信代理边界内才适合用于判断客户端地址。

## HTTP 缓存与 Redis 缓存不同

| 值 | 含义 |
| --- | --- |
| `no-store` | 不存储响应 |
| `no-cache` | 可以存储，但使用前需要重新验证 |
| `max-age=60` | 新鲜期 60 秒 |
| `private` | 限制共享缓存存储 |
| `public` | 允许共享缓存按规则存储 |

HTTP 缓存位于浏览器、代理或 CDN 等层；Redis 是服务端应用访问的数据服务。写入 `Cache-Control: no-store` 不会删除 Redis 键，给 Redis 设置 TTL 也不会自动生成 HTTP 缓存头。

如果响应随 `Origin` 或 `Accept-Encoding` 变化，应理解 `Vary` 对共享缓存区分版本的作用。CORS 中间件会根据配置处理相应 CORS 响应头，不需要在每个业务函数里重复拼装。

## Cookie 的读取与设置

项目的演示逻辑：

```python
from typing import Annotated

from fastapi import Cookie, Response


@LogRouter.get("/setCookie")
async def set_cookie(
    response: Response,
    ads_id: Annotated[str | None, Cookie()] = None,
):
    response.set_cookie(
        key="ads_id",
        value="ads_id-cookie-session-value",
        max_age=3600,
        domain="127.0.0.1",
        path="/",
        httponly=True,
    )
    return {"ads_id": ads_id}
```

这次返回体中的 `ads_id` 是客户端本次传来的值；新 Cookie 通过响应头发给客户端，供下一次请求携带。

```bash
curl -i -c /tmp/fastapi-demo-cookies.txt \
  "http://127.0.0.1:8801/apiCommon/test/log/setCookie"

curl -i -b /tmp/fastapi-demo-cookies.txt \
  "http://127.0.0.1:8801/apiCommon/test/log/setCookie"
```

| 属性 | 作用与限制 |
| --- | --- |
| `max_age` | 从设置时起的有效秒数 |
| `expires` | 绝对过期时间，同时设置时通常以 `max_age` 为准 |
| `domain` | 限制接收主机；不设置时为 host-only Cookie |
| `path` | 请求路径匹配范围，不是权限边界 |
| `httponly` | 阻止 JavaScript 通过 `document.cookie` 读取 |
| `secure` | 用于限制通过安全连接传输 |
| `samesite` | 控制跨站请求携带行为；`None` 通常还需要 `Secure` |

项目写死 `127.0.0.1` 用于本地演示，换成 `localhost` 或真实域名时需要重新考虑作用域。未指定到期时间的是会话 Cookie，浏览器的会话恢复功能也可能保留它，不能据此保证“关闭窗口立即删除”。

`Set-Cookie` 不能把多个 Cookie 简单用逗号拼成一个头，使用 `set_cookie()` 多次调用更可靠。

## 跨域读取自定义响应头

能在浏览器网络面板看到 `X-Request-Id`，不代表 JavaScript 一定能读取它。跨域时需要暴露对应头部，当前配置包含：

```python
CORS_EXPOSE_HEADERS: list[str] = ["X-Request-ID"]
```

头部大小写差异不影响匹配。跨域 Cookie 还需要客户端 credentials、允许凭据的 CORS 配置和 Cookie 自身属性共同满足，见 [中间件与跨域](../003应用机制/002中间件与跨域.md)。
