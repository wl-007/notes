# 参数来源、模型与校验

对应提交：`e23de67`（2026-09-30，接口参数定义），`de407fd`（2026-10-09，参数解析情况）。

```bash
curl -X POST "http://127.0.0.1:8801/apiCommon/test/dept/items" \
  -H "Content-Type: application/json" \
  -d '{"name":"示例商品","price":998}'
```

当前接口返回 `name` 和 `price`。理解为什么 JSON 会进入 `item`，需要先区分参数来源。

## FastAPI 从哪里取值

| 声明 | 默认来源 | 例子 |
| --- | --- | --- |
| 名字出现在路径模板中 | 路径 | `/detail/{dept_id}` 中的 `dept_id: int` |
| 其他普通标量参数 | 查询字符串 | `skip: int = 0` |
| Pydantic 模型参数 | JSON 请求体 | `item: Item` |
| `Annotated[Model, Query()]` | 查询字符串 | 一组过滤条件 |
| `Header()` / `Cookie()` | 请求头 / Cookie | 见下一篇 |
| `Form()` / 表单依赖 | 表单 | OAuth2 登录 |
| `Depends()` | 依赖调用结果 | 数据库会话、当前用户 |

HTTP 方法本身不决定模型参数来源。GET 接口直接写一个 `BaseModel` 参数，不能据此认为它就变成查询参数。

## 查询与路径参数

```python
from typing import Annotated

from fastapi import APIRouter, Path, Query

router = APIRouter()


@router.get("/detail/{dept_id}")
async def detail(
    dept_id: Annotated[int, Path(gt=0)],
    name: Annotated[str | None, Query(max_length=50, alias="dept-name")] = None,
):
    return {"id": dept_id, "name": name}
```

这是独立示例，展示 `Path` 与 `Query` 的校验方式。项目现有 `/detail/{dept_id}` 只声明了整数类型，没有加入 `gt=0`。

`Annotated` 的第一个参数是类型，后续参数是附加元数据。`Query`、`Path` 是参数声明工具，不是给函数加的装饰器。

| 常见约束 | 含义 |
| --- | --- |
| `gt` / `ge` | 大于 / 大于等于 |
| `lt` / `le` | 小于 / 小于等于 |
| `min_length` / `max_length` | 长度边界 |
| `pattern` | 正则表达式校验 |
| `alias` | 对外使用的参数名 |

校验失败默认是 HTTP 422；当前项目没有将 `RequestValidationError` 改成 400。

### 可空不等于可省略

```python
q: str                     # 必填，不能为 None
q: str | None              # 类型允许 None，但没有默认值，仍为必填
q: str | None = None       # 可以省略
```

查询字符串中的 `q=null` 通常是文本 `"null"`，不是 JSON 的 `null`。

## 请求体、Field 和嵌套对象

```python
from pydantic import BaseModel, Field


class Image(BaseModel):
    url: str
    name: str


class Item(BaseModel):
    name: str = Field(min_length=1, max_length=100)
    price: float = Field(gt=0)
    tags: list[str] = Field(default_factory=list)
    image: Image | None = None


@router.post("/items")
async def create_item(item: Item):
    return item
```

`Field` 描述模型字段；`Body` 描述路由参数在请求体中的组织方式。一个模型参数默认直接对应 JSON 对象；多个模型参数会按参数名形成外层对象。

项目中的 `PUT /apiCommon/test/dept/items107/123` 同时接收 `item` 和 `user`：

```json
{
  "item": {"name": "示例商品", "price": 9.99},
  "user": {"username": "zhangsan", "full_name": "张三"}
}
```

单个参数也可以用 `Annotated[Item, Body(embed=True)]` 明确要求 `{"item": {...}}`。普通标量如需放入请求体，也要显式使用 `Body()`，否则通常会被解释为查询参数。

项目的嵌套模型演示位于 `PUT /apiCommon/test/dept/items147/{item_id}`。其中 `tags` 是集合，JSON 仍使用数组，但重复元素会被去重。

## 查询参数模型

```python
from typing import Annotated, Literal

from fastapi import Query
from pydantic import BaseModel, Field


class FilterParams(BaseModel):
    limit: int = Field(default=10, gt=0, le=100)
    offset: int = Field(default=0, ge=0)
    order_by: Literal["created_at", "updated_at"] = "created_at"
    tags: list[str] = Field(default_factory=list)


@router.get("/items/")
async def list_items(filters: Annotated[FilterParams, Query()]):
    return filters
```

项目对应接口是 `GET /apiCommon/test/dept/items/`，注意尾部斜杠。数组查询参数可重复传入：

```bash
curl "http://127.0.0.1:8801/apiCommon/test/dept/items/?limit=5&tags=python&tags=fastapi"
```

## Pydantic 模型还负责什么

| 能力 | 常见写法 | 注意点 |
| --- | --- | --- |
| 类型转换与校验 | `age: int` | 默认可能将 `"18"` 转为 `18`，严格模式需另配 |
| 自定义校验 | `@field_validator` | `before` 处理原始输入，`after` 处理已转换结果 |
| 输出字典 | `model_dump()` | 默认仍可能保留 datetime 等 Python 对象 |
| JSON 兼容输出 | `model_dump(mode="json")` | 适合缓存、JSON 响应内容准备 |
| 解析对象 | `model_validate(value)` | 从 ORM 属性读取需配置 `from_attributes=True` |
| 部分更新 | `model_dump(exclude_unset=True)` | 区分未提供字段与显式提供 `null` |
| 多余字段控制 | `ConfigDict(extra="forbid")` | 项目系统用户采用 `extra="ignore"`，会忽略额外字段 |

输入 Schema、输出 Schema 和数据库 Model 职责不同。模型通过校验不表示用户有权限，也不表示数据库唯一约束一定满足。

## 日期、时区与时间戳

接口优先约定带时区的日期时间：

```text
2026-09-30T10:00:00+08:00
2026-09-30T02:00:00Z
```

普通 `datetime` 也可能接受没有时区的字符串。需要强制时区时可以使用 Pydantic 的 `AwareDatetime`，不要只靠接口说明约束。

项目的 `POST /apiCommon/test/dept/items176` 接收：

```bash
curl -X POST "http://127.0.0.1:8801/apiCommon/test/dept/items176" \
  -H "Content-Type: application/json" \
  -d '{
    "name":"alarm1",
    "start_time":"2026-09-30T10:00:00+08:00",
    "end_time":"2026-09-30T12:00:00+08:00"
  }'
```

`/items187` 也是 **POST**，其 `before` 校验器将数字按 Unix **秒**转换为东八区时间：

```python
from datetime import datetime, timedelta, timezone

from pydantic import BaseModel, field_validator

CST = timezone(timedelta(hours=8))


class AlarmQuery(BaseModel):
    name: str
    start_time: datetime
    end_time: datetime

    @field_validator("start_time", "end_time", mode="before")
    @classmethod
    def ts_to_datetime(cls, value):
        if isinstance(value, (int, float)):
            return datetime.fromtimestamp(value, tz=CST)
        return value
```

```bash
curl -X POST "http://127.0.0.1:8801/apiCommon/test/dept/items187" \
  -H "Content-Type: application/json" \
  -d '{"name":"alarm1","start_time":1790179200,"end_time":1790186400}'
```

时间戳表示一个绝对时刻，显示时才选择时区。上面的自定义转换不会自动识别毫秒；不能直接传 JavaScript `Date.now()` 的结果。当前模型也没有校验结束时间必须晚于开始时间，如有业务需求需另加模型级校验。

## 当前源码中的重复路由

`dept/controller.py` 两次注册了 `GET /items/{item_id}`。前者接收字符串 `item_id` 和 `needy`，后者演示 `Path` 和 `dept-name`。请求实际先到前者，因此不能把后者当作可直接验证的校验接口。
