# 依赖注入、公共参数与日志

对应提交：`d48f1eb`（2026-10-13，依赖注入与公共参数）。数据库、认证和 Redis 后续都沿用了这一机制。

项目把常用依赖写成类型别名：

```python
DbSession = Annotated[AsyncSession, Depends(db_getter)]
CurrentUser = Annotated[UserModel, Depends(get_current_user)]
RedisDep = Annotated[Redis | None, Depends(redis_getter)]
```

路由声明 `db: DbSession` 后，FastAPI 会调用对应依赖并把结果传入，不是把 `db` 当成查询参数。

## 从公共查询参数理解 Depends

```python
from typing import Annotated

from fastapi import Depends, FastAPI

app = FastAPI()


async def common_parameters(q: str | None = None, skip: int = 0, limit: int = 100):
    return {"q": q, "skip": skip, "limit": limit}


CommonsDep = Annotated[dict, Depends(common_parameters)]


@app.get("/items")
async def list_items(commons: CommonsDep):
    return commons
```

这是独立可运行示例。项目仍保留 `CommonsDep` 定义，但当前数据库用户路由已改用分页模型，不再直接注入它。历史用法可以通过 `git show d48f1eb:backend/app/api/test/user/controller.py` 查看。

依赖本身也支持参数校验、子依赖和异步函数。`Depends(common_parameters)` 传入的是函数，不能写成启动时就执行的 `Depends(common_parameters())`。

## 依赖缓存与对象生命周期

| 机制 | 作用范围 | 项目例子 |
| --- | --- | --- |
| Depends 默认缓存 | 同一个请求中的同一个依赖 | 路由与 `CurrentUser` 复用 `DbSession` |
| `lru_cache` | 当前进程内的函数结果缓存 | Settings |
| `app.state` | 当前应用实例共享状态 | Redis 客户端 |
| Redis 键 | Redis 服务中的数据 | 热门用户榜单 |

这些缓存不能互相代替。`Depends(..., use_cache=False)` 可以要求重新求值，但不应为了“避免重复数据”就给数据库会话随意关掉缓存。

当前 `get_current_user()` 自身依赖 `DbSession`，路由也依赖它。默认缓存使二者在一次请求中共享会话；这有利于统一事务边界，但不能把同一个 AsyncSession 用于并发任务。

## 带 yield 的资源依赖

```python
async def db_getter():
    async with async_db_session() as session:
        async with session.begin():
            yield session
```

`yield` 前获取资源，之后的退出逻辑负责清理或提交/回滚。请求抛出的异常会经过依赖上下文，不能在依赖里捕获后无声吞掉。

当前 `DbSession` 未指定 scope，使用 request scope，退出发生在响应发送之后。若需要提交失败在响应发送前转成错误，需要设计 function scope 等事务边界；这属于实现调整，详见 [MySQL 与异步会话](../004数据访问/001MySQL与异步会话.md)。

## 公共分页模型

项目 `PaginationQueryParam` 提供：

| 字段 | 默认值 | 边界 |
| --- | --- | --- |
| `page_no` | 1 | 大于等于 1 |
| `page_size` | 10 | 1 到 100 |
| `order_by` | None | 接收 `id:desc,nickname:asc` |

业务查询模型继承分页参数，并加入搜索字段：

```python
class UserQueryParam(PaginationQueryParam):
    username: str | None = Field(default=None, max_length=50)
    nickname: str | None = Field(default=None, max_length=50)
```

Controller 用 `Annotated[UserQueryParam, Query()]` 接收它，Service 计算：

```python
offset = (query.page_no - 1) * query.page_size
```

```bash
curl -G "http://127.0.0.1:8801/apiCommon/sys/user" \
  -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "page_no=1" \
  --data-urlencode "page_size=10" \
  --data-urlencode "order_by=id:desc,nickname:asc"
```

`TOKEN` 为登录后获取的实际令牌。

### 当前排序解析的类型边界

`order_by` 声明为 `str | None`，但 `after` 校验器把传入字符串改为 `list[dict[str, str]]`。字段声明与运行时值因此不一致；`mode="after"` 不会自动让这种返回值与注解匹配。

没有显式传值时，Pydantic 默认不验证该字段的默认值，`None` 可能保持原样。Service 用 `isinstance(query.order_by, list)` 分支处理，其余情况交给 CRUD 使用默认 `id DESC`。

更清晰的后续设计是保留原始字符串，另用属性或函数产出排序列表，而不是让同一个字段在校验前后改变类型。系统用户 CRUD 还有列白名单，解析成功不等于任意字段都可以参与排序。

## 用 Loguru 记录应用日志

`backend/app/core/logger.py` 移除默认 handler，再添加格式化的 stdout handler。导入模块后配置执行一次，可使用：

```python
from app.core.logger import logger

logger.info("查询用户列表 page_no={}", query.page_no)
```

当前日志显示时间、级别、模块、函数和行号。它主要用于应用自身日志，没有实现文件轮转、日志采集、请求 ID 串联，也没有自动接管 Uvicorn 标准日志。

异常捕获后需要堆栈时可使用 `logger.exception()`；常规业务日志不要记录原始密码或完整 Bearer 令牌。stdout 日志是否在服务退出后仍能查询，取决于进程管理器、容器日志驱动或外部采集设施，而不是 Loguru 本身。

## 测试时如何替换依赖

独立测试可以使用应用的覆盖字典：

```python
app.dependency_overrides[db_getter] = fake_db_getter
# 测试结束后清理，防止影响其他用例。
app.dependency_overrides.clear()
```

依赖覆盖让 HTTP 层测试不必真的连接数据库，但它不能验证 SQL、事务隔离或真实 Redis 重连行为，这些需要相应集成测试。
