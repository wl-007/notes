# JWT 登录、密码哈希与账号权限

对应提交：`7101210`（2026-10-30，新增用户 CRUD）。登录的请求与响应格式后来由 `1ba26fd` 调整，下面按当前实现说明。

```text
注册 → bcrypt 哈希入库
登录 → 校验密码 → 签发 JWT
访问接口 → 读取 Bearer → 验签与过期检查 → 查询用户 → 检查状态与密码戳
修改 / 删除 → 继续检查是否为账号本人
```

认证回答“你是谁”，授权回答“你能操作什么”。JWT 只参与其中一部分，不能仅凭请求带了令牌就允许所有操作。

## 密码为什么要存哈希

系统用户 `user` 表存储 `password_hash`，不存原始密码：

```python
def hash_password(password: str) -> str:
    return bcrypt.hashpw(
        password.encode("utf-8"), bcrypt.gensalt()
    ).decode("ascii")
```

哈希不是可逆加密。bcrypt 使用盐和可调计算成本，登录时用 `checkpw()` 验证，不是重新生成随机盐后直接比较字符串。

当前输入要求密码至少 8 个字符，同时限制 UTF-8 编码后最多 72 字节。中文等字符可能占多个字节，所以不能只看字符串长度。这个上限对应当前 bcrypt 使用方式，不是所有密码哈希算法的通用限制。

哈希与验证是耗时计算，Service 使用 `run_in_threadpool()`，避免在异步事件循环中直接计算。线程池不会无限扩容，高并发登录还需要容量评估和限流；项目尚未实现登录限流、密码找回或多因素认证。

## JWT 包含什么

JWT 的常见签名形式由 header、payload、signature 三部分组成。Base64URL 编码不提供保密性，拿到令牌的人通常可以读到声明，所以不要把原始密码等秘密放进去。

项目使用 HS256 签名，payload 包含：

| 声明 | 项目含义 |
| --- | --- |
| `sub` | 用户 ID，存为字符串 |
| `iat` | 签发时间，UTC |
| `exp` | 过期时间，默认签发后 60 分钟 |
| `pwd` | 根据当前密码哈希生成的 HMAC 戳 |

`JWT_SECRET_KEY` 由环境提供，至少 32 字节。HS256 的签发与验签使用同一个秘密，泄露后攻击者可能伪造令牌；更换密钥也会使旧令牌验签失败。多 worker 需要使用一致的有效配置。

JWT 解决的是声明完整性和签发方校验，不会自动提供退出登录、撤销列表、刷新令牌或用户权限系统。

## 当前用户依赖怎样验证令牌

`OAuth2PasswordBearer` 负责从 `Authorization: Bearer ...` 提取字符串，真正验证由 `get_current_user()` 完成：

1. 没有令牌：401，“请先登录”。
2. 验签、过期或 `sub` 校验失败：401。
3. 查询数据库，过滤软删除用户。
4. 用户不存在或未启用：401。
5. 用 `hmac.compare_digest()` 比较密码戳，不一致：401。
6. 返回 ORM 用户对象，供 `CurrentUser` 注入。

验签时固定 `algorithms=["HS256"]`，不让令牌自己决定接受什么算法。

由于每次都查数据库，当前机制不是完全无状态认证。优点是删除账号、禁用账号和修改密码可以影响已有令牌；代价是受保护请求仍依赖数据库。

密码戳是 HMAC，不是直接把 bcrypt 字符串放进 token。修改密码后哈希变化，旧戳不匹配，旧令牌在下一次鉴权时失效。

## 接口与权限范围

统一前缀：`/apiCommon/sys/user`。

| 方法与路径 | 入参 | 当前权限 |
| --- | --- | --- |
| `POST /register` | JSON：username、password、可选 nickname | 匿名可注册 |
| `POST ""` | 同注册 | 隐藏的兼容入口 |
| `POST /login` | URL 编码表单 | 匿名可登录 |
| `GET /me` | Bearer | 当前登录账号 |
| `GET ""` | 分页、筛选、排序 | 任意有效登录账号 |
| `GET /{user_id}` | 路径 ID | 任意有效登录账号 |
| `PUT /{user_id}` | JSON：nickname / password | 只能修改本人 |
| `DELETE /{user_id}` | 路径 ID | 只能删除本人，软删除 |
| `GET /popular` | 可选 `date` | 任意有效登录账号 |

项目尚未实现管理员角色、RBAC 或“只能查询本人详情”的限制。列表和详情权限与修改权限不同。

## 注册、登录和读取当前用户

前置条件：MySQL 表已准备，环境中已设置有效的 JWT 密钥。

```bash
curl -i -X POST "http://127.0.0.1:8801/apiCommon/sys/user/register" \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"demo-password-123","nickname":"Alice"}'
```

注册成功返回 HTTP 201；重复用户名返回 409。Service 既做查询检查，也捕获数据库唯一约束冲突。

```bash
curl -X POST "http://127.0.0.1:8801/apiCommon/sys/user/login" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "username=alice" \
  --data-urlencode "password=demo-password-123"
```

```json
{"access_token": "<实际令牌>", "token_type": "bearer"}
```

把本次返回的令牌设为 shell 变量 `TOKEN` 后：

```bash
curl "http://127.0.0.1:8801/apiCommon/sys/user/me" \
  -H "Authorization: Bearer $TOKEN"
```

示例密码仅用于本地学习；令牌通过 HTTPS 传输，避免放进 URL 查询参数。

## 修改、删除后会发生什么

```bash
curl -X PUT "http://127.0.0.1:8801/apiCommon/sys/user/1" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"nickname":"Alice Updated"}'
```

将 `1` 替换为本人真实 ID。修改昵称不使令牌失效；修改密码会使已有令牌失效，需要重新登录。删除设置 `is_deleted=True`，后续鉴权查询不到该用户。

“退出登录”若只在客户端删除令牌，并不会让其他已经复制的令牌立即失效。当前没有独立退出接口、refresh token 或 Redis 黑名单，不能把热门用户缓存误认为令牌存储。
