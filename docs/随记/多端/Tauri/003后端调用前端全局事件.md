# Tauri 后端调用前端全局事件

## 全局事件与 command / Channel 的差异

- `command`：前端主动调用后端，一问一答。
- `Channel`：一次调用期间，后端向后端方向持续推流，调用结束通道销毁。
- 全局事件：Rust 通过 `AppHandle.emit` 主动广播，前端通过 `listen` 随时订阅；事件不依赖某次调用的生命周期。

Tauri 事件是进程内发布订阅，不是 MQTT：没有 broker、QoS，也不保留历史消息。页面还没监听就发送的事件会丢失，所以要先 `listen`，再触发发送。

## 事件命名

示例使用 `模块名:动作` 的命名格式：

```text
welcome:hello
clock:tick
progress:update
```

Rust 和前端各自集中维护事件名常量，避免两边拼写不一致。

## Rust 端发送

```rust
use tauri::Emitter;

app.emit("welcome:hello", serde_json::json!({
  "message": "欢迎消息已从 Rust 到达前端",
  "appName": app.package_info().name,
  "emittedAt": timestamp,
}))?;
```

后台持续推送时，可以 `app.clone()` 到线程里，按固定次数循环 `emit`。

## 前端监听

```ts
import { listen } from "@tauri-apps/api/event";

const unlisten = await listen("clock:tick", (event) => {
  console.log(event.payload);
});
```

组件卸载时要调用 `unlisten()`，避免监听器泄漏。项目里把这层封装在 `src/services/events.ts`，页面只关心事件负载类型。

## 示例触发方式

欢迎事件在页面监听就绪后自动触发；时钟和进度由按钮通过 `command_rust` 启动。触发仍然走前端调用后端，但真正的数据推送方向是后端 -> 前端。
