# Tauri 资源打包与媒体播放

## 内置资源打包

放在 `src-tauri/data` 下的媒体文件不会自动进入应用。需要在 `tauri.conf.json` 里声明 `bundle.resources`，Tauri 会把文件复制到 `$RESOURCE/data` 下，保持原始目录结构。

```json
{
  "bundle": {
    "resources": ["data/**/*"]
  },
  "app": {
    "security": {
      "assetProtocol": {
        "enable": true,
        "scope": ["$RESOURCE/**/*"]
      }
    }
  }
}
```

`assetProtocol` 负责把磁盘文件通过 `asset://` URL 提供给 WebView。scope 只放开 `$RESOURCE`，不要把整个磁盘都放进去。

新增资源文件后，如果 `tauri dev` 已经在运行，需要重启 `pnpm tauri dev`，CLI 才会把新文件重新复制到开发资源目录。

另外 `Cargo.toml` 里 `tauri` 依赖需要开启 `protocol-asset` feature，否则 `asset://` 协议不可用：

```toml
tauri = { version = "2", features = ["protocol-asset"] }
```

## 前端播放内置文件

先通过 `resolveResource` 拿到资源绝对路径，再用 `convertFileSrc` 转成 WebView 能加载的 URL，最后交给原生 `<audio>` / `<video>`。

```ts
import { resolveResource } from "@tauri-apps/api/path";
import { convertFileSrc } from "@tauri-apps/api/core";

const filePath = await resolveResource("data/music/xxx.mp3");
const src = convertFileSrc(filePath);
```

浏览器原生负责加载、进度和 seek，不需要 Rust 用 `Channel` 推送字节。

## Rust 扫描媒体列表

示例项目通过 `command_rust` 的 `media:list` 任务扫描 `$RESOURCE/data`，按扩展名把文件归类为 `audio` 或 `video`，返回 `{ name, kind, path, filePath, size }` 列表。`filePath` 是资源在磁盘上的绝对路径，前端直接交给 `convertFileSrc`，不再需要先 `resolveResource`。

Rust 端通过 `webview.app_handle().path().resource_dir()` 获取资源目录，用标准库递归遍历即可，不需要额外 crate。

## 播放本机任意文件

内置资源用 asset 协议；本机任意文件不要为了播放而把 asset scope 放开到全盘。使用原生文件选择器读取 File，再通过 `URL.createObjectURL(file)` 生成临时 URL 播放。

页面里把选择拆成“本地音频”和“本地视频”两个入口，选视频时固定用 `<video>`，避免因为 MIME/扩展名识别不准而落到 `<audio>`。

```tsx
<input
  accept="audio/*,video/*"
  type="file"
  onChange={(event) => {
    const file = event.target.files?.[0];
    if (file) {
      const src = URL.createObjectURL(file);
      // 交给 <audio> 或 <video>
    }
  }}
/>
```

这种方式不需要新增 Tauri 插件，也不会把磁盘任意路径暴露给 WebView。
