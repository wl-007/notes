# Tauri 应用菜单（JS API）

## JS API 就够了

应用顶部菜单栏不需要写任何 Rust 代码，`@tauri-apps/api/menu` 提供了完整能力：

- `Menu.new(options)` 创建菜单，`menu.setAsAppMenu()` 挂为应用级菜单（macOS 屏幕顶部 / Windows 窗口内）
- 权限方面，`core:default` 已包含 `core:menu:default`（含 `allow-set-as-app-menu` 等），**无需改 capabilities**
- 自定义菜单项的 `action` 回调基于 Channel 实现，点击直达前端，不用监听事件

## 菜单项的两类写法

```ts
import { Menu } from "@tauri-apps/api/menu";

// 1. 自定义项：带 id 和 action 回调，点击后回调直达前端。
function item(id: string, text: string, accelerator?: string) {
  return { id, text, accelerator, action: () => console.log(id) };
}

// 2. 预定义项：系统原生行为（撤销/复制/粘贴/退出/最小化等），不触发 action。
function native(itemType: "Copy" | "Cut" | "Quit" | /* ... */) {
  return { item: itemType, text: "复制" };
}
```

预定义项的完整类型见 `PredefinedMenuItemOptions`：`Separator / Copy / Cut / Paste / SelectAll / Undo / Redo / Minimize / Maximize / Fullscreen / Hide / HideOthers / ShowAll / CloseWindow / Quit / Services / BringAllToFront / { About: AboutMetadata | null }`。

## 完整菜单树（嵌套 options 一次创建）

macOS 约定第一个子菜单作为"应用菜单"，放关于/隐藏/退出等系统级命令。

```ts
const menu = await Menu.new({
  items: [
    {
      text: "应用",
      items: [
        { item: { About: null }, text: "关于" },
        { item: "Separator" },
        { item: "Hide", text: "隐藏" },
        { item: "Quit", text: "退出" },
      ],
    },
    {
      text: "文件",
      items: [
        item("file-new", "新建文件", "CmdOrCtrl+N"),
        item("file-open", "打开文件", "CmdOrCtrl+O"),
        item("file-save", "保存", "CmdOrCtrl+S"),
        { item: "Separator" },
        { item: "CloseWindow", text: "关闭窗口" },
      ],
    },
    // 编辑（撤销/复制/粘贴等预定义项）、视图、窗口、帮助 ...
  ],
});

// 挂为应用级菜单；返回被替换的旧菜单（首次为 null），记得 close 释放资源。
const previous = await menu.setAsAppMenu();
await previous?.close();
```

## 应用级菜单 + React 页面的架构

菜单是**应用级**的，但页面是有生命周期的。如果菜单初始化放在某个页面里，会出现两个问题：
没进过那个页面菜单就不存在；离开后点击无人响应。正确做法是**初始化与订阅分离**：

- **初始化**在 App 启动时（`App.tsx` 的 useEffect）调用一次，幂等（重复调用返回同一个 Promise）
- **订阅**由各页面通过 `onMenuAction()` 完成，挂载时订阅、卸载时取消
- 分发器广播给订阅者集合，无人订阅时静默，不报错

```ts
// services/menu.ts
const listeners = new Set<(id: string) => void>();
let initPromise: Promise<void> | null = null;

export function initAppMenu(): Promise<void> {
  initPromise ??= (async () => {
    // 分发器：广播给所有订阅者（无人订阅时静默）。
    const menu = await Menu.new(
      buildMenuOptions((id) => listeners.forEach((listener) => listener(id))),
    );
    const previous = await menu.setAsAppMenu();
    await previous?.close();
  })();
  return initPromise;
}

export function onMenuAction(listener: (id: string) => void): () => void {
  listeners.add(listener);
  return () => listeners.delete(listener);
}
```

```tsx
// App.tsx：启动时初始化，不依赖任何页面
useEffect(() => {
  void initAppMenu();
}, []);

// 任意页面：挂载订阅、卸载取消
useEffect(() => {
  const unsubscribe = onMenuAction((id) => handleMenuAction(id));
  return unsubscribe;
}, []);
```

菜单 action 的闭包只引用 `listeners` 集合，与页面生命周期完全解耦。

## 模拟行为分发

真实应用中菜单点击是"新建文档/调起文件对话框/写盘"等业务；演示里用 switch 按 id 模拟：

```ts
switch (id) {
  case "file-new":   // 文件列表加一个未保存的未命名文件
  case "file-open":  // 模拟打开 示例文档.md
  case "file-save":  // 把所有未保存文件标记为已保存
  case "view-zoom-in":   // 缩放 +10%，上限 200%
  case "view-zoom-out":  // 缩放 -10%，下限 50%
  case "view-zoom-reset": // 重置 100%
  case "help-guide":       // 打开使用说明弹窗
  case "help-check-update": // toast 提示已是最新版本

```

## 注意事项

- **纯浏览器环境（pnpm dev）没有菜单能力**，`Menu.new()` 会失败，页面需要 catch 并给出提示，只在 `pnpm tauri dev` 下可用。
- 预定义项**不会**触发 action（或 `tauri://menu` 事件），它们由系统直接处理；只有自定义项有点击回调。
- 快捷键写法与 Rust 端一致：`"CmdOrCtrl+N"`；非法快捷键会被静默忽略。
- `setAsAppMenu()` 是应用级，`setAsWindowMenu(window)` 是窗口级（macOS 不支持后者，只能用应用级）。
