# Tauri 前端调用后端

## 设计思路

前端不按功能注册多个 Tauri 命令，而是统一调用一个 `command_rust`。后端通过 `task` 参数把请求分发给不同模块，每个任务文件只负责自己的逻辑，这样命令入口清晰，后续扩展任务也不会把 `lib.rs` 撑大。

前端调用：

```ts
import { invoke } from "@tauri-apps/api/core";

await invoke("command_rust", {
  task: "echo",
  payload: { message: "你好，Tauri" },
});
```

Rust 入口：

```rust
#[tauri::command]
pub async fn command_rust(
  webview: tauri::Webview,
  task: String,
  payload: serde_json::Value,
) -> Result<serde_json::Value, String> {
  match task.as_str() {
    "echo" => echo::handle(payload),
    "system" => system::handle(),
    "download" => download::handle(webview, payload).await,
    _ => Err(format!("unknown task: {task}")),
  }
}
```

## 三个前端调用后端示例

### echo 回显

接收 `{ message }`，返回 `{ message, length }`。`length` 用字符数计算，中文也能正确显示。

### system 系统信息

返回 `os`、`arch`、`family`、`cpus`、`pid`，数据全部来自 Rust 标准库，不需要额外依赖。

### download Channel 流式下载

`Channel` 是 Tauri 的回调式流式通道。前端创建一个 `Channel`，随 `command_rust` 的 `payload` 一起传给后端；Rust 端从 payload 中解析出 `JavaScriptChannelId`，再通过 `channel_on(webview)` 转成真正的 `Channel`，之后可以多次 `send`。

前端：

```ts
import { Channel } from "@tauri-apps/api/core";

const channel = new Channel<DownloadChunk>((chunk) => {
  console.log(chunk.percent);
});

await invoke("command_rust", {
  task: "download",
  payload: {
    name: "demo-1MB.zip",
    chunkCount: 10,
    channel,
  },
});
```

Rust 端：

```rust
let channel: Channel<DownloadChunk> = payload.channel.channel_on(webview);
channel.send(DownloadChunk { index: 1, percent: 10, done: false })?;
```

Channel 适合下载进度、分片文件、视频/音频流这类持续推送场景。它在一次命令调用内存在，命令结束或 Channel 被丢弃时会自动清理回调。
