# Electron 基本知识

## 主进程与渲染进程通信（IPC）

Electron 应用通常包含三类进程：

- 主进程（main）：管理窗口、应用生命周期，可以访问 Node.js 能力。
- 渲染进程（renderer）：负责页面 UI，运行在浏览器环境。
- preload：渲染进程加载前执行，是主进程与渲染进程之间的安全桥梁。

渲染进程不能直接调用 Node.js API，需要通过 preload 暴露的接口与主进程通信。
这个机制统称为 IPC（Inter-Process Communication）。

### 常用通信方式

1. `invoke / handle`：请求响应式，适合“渲染进程调用，主进程返回结果”。

   ```ts
   // 主进程
   ipcMain.handle('app:ping', () => {
     return { message: 'pong', time: Date.now() }
   })

   // 渲染进程（通过 preload 暴露的 api）
   const result = await window.api.ping()
   ```

2. `send / on`：事件式，适合“主进程主动推送”或“发送后由主进程异步回复”。

   ```ts
   // 主进程收到消息后，通过 event.sender.send 回推
   ipcMain.on('app:message', (event, content) => {
     event.sender.send('app:message-reply', { content: `收到：${content}` })
   })
   ```

3. `sendSync`：同步通信，会阻塞渲染进程，一般不推荐使用。

### 安全实践

- 保持 `contextIsolation: true`，让 preload 与页面上下文隔离。
- 使用 `contextBridge` 暴露白名单 API，不要把整个 `ipcRenderer` 直接交给页面。
- 渲染进程只应看到 `window.api` 这类收窄接口，不应知道具体通道名。
- 生产环境尽量开启 `sandbox: true`。
- 通道常量集中管理，避免在主进程、preload、渲染进程各处手写字符串。

### 工程实践（本项目 electron-demo）

1. 通道常量集中在 `src/shared/ipc.ts`：

   ```ts
   export const IpcChannels = {
     ping: 'app:ping',
     getAppInfo: 'app:get-info',
     message: 'app:message',
     messageReply: 'app:message-reply'
   } as const
   ```

2. 主进程按职责拆分：

   - `src/main/index.ts`：应用入口与生命周期。
   - `src/main/windows/mainWindow.ts`：窗口创建与加载。
   - `src/main/ipc/ipcHandler.ts`：注册 IPC 处理器。

3. preload 只暴露业务方法：

   ```ts
   const api = {
     ping: () => ipcRenderer.invoke(IpcChannels.ping),
     getAppInfo: () => ipcRenderer.invoke(IpcChannels.getAppInfo),
     sendMessage: (content) => ipcRenderer.send(IpcChannels.message, content),
     onMessageReply: (callback) => {
       const listener = (_event, reply) => callback(reply)
       ipcRenderer.on(IpcChannels.messageReply, listener)
       return () => ipcRenderer.removeListener(IpcChannels.messageReply, listener)
     }
   }
   ```

4. 渲染进程只调用 `window.api`，事件订阅返回取消函数，组件卸载时清理。

### 关键总结

- IPC 通道名集中管理，避免字符串漂移。
- preload 是安全边界，暴露面越小越安全。
- `invoke / handle` 适合请求响应，`send / on` 适合事件推送。
- 渲染进程只依赖 `window.api` 的类型化接口，不直接接触 `ipcRenderer`。
