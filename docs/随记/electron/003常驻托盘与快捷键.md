# 第 2 篇：常驻托盘、快捷键切换与失焦隐藏

本篇对应 `src/main/resident-window.ts`，以及 `src/main/index.ts` 中的生命周期处理。目标行为是：应用启动后不弹窗、不占 Dock 或任务栏，通过菜单栏图标或快捷键呼出，点其他应用后收起。

## 1. 先把几个“栏”分清

| 名称 | 在哪里 | 对应能力 |
| --- | --- | --- |
| 窗口标题栏 | 窗口顶部的拖动区和关闭等按钮 | `frame`、`titleBarStyle` |
| Windows 任务栏 | 屏幕底部等位置的运行应用入口 | `skipTaskbar` |
| macOS Dock | 屏幕底部或侧边的应用图标 | `app.dock`、`LSUIElement` |
| macOS 状态栏图标 | 顶部菜单栏右侧的工具图标 | `Tray` |
| Windows/Linux 系统托盘 | 系统通知区域 | `Tray` |
| 应用菜单 | “文件、编辑”等菜单项 | `Menu`、窗口菜单相关 API |

“只在菜单栏出现图标”是几项设置共同组成的结果，没有一个 `utoolsMode: true` 开关。

## 2. 第一步：让应用启动时保持隐藏

创建窗口时配置：

```ts
const mainWindow = new BrowserWindow({
  show: false,
  frame: false,
  skipTaskbar: true
  // 其余参数见上一章，这里只展示相关项。
})
```

不要再在 `ready-to-show` 中无条件调用 `show()`。窗口创建和页面加载仍会进行，只是用户暂时看不到它。

`frame: false` 去掉标题栏，并不阻止系统发出关闭请求；关闭行为后面仍要处理。

## 3. 第二步：隐藏 Dock 和任务栏图标

### 3.1 Windows 任务栏

创建窗口时使用 `skipTaskbar: true`。已有窗口也有对应的运行时方法：

```ts
// 主进程：适用于支持该能力的平台。
mainWindow.setSkipTaskbar(true)
```

项目直接用构造器配置即可。不要把它当成 macOS 隐藏 Dock 的完整解决方案。

### 3.2 macOS 开发运行时

项目在 Electron ready 后调用：

```ts
// dock 是 macOS 能力，可选链让代码可以在其他平台运行。
app.dock?.hide()
```

需要恢复 Dock 时，可以调用 macOS 的 `app.dock.show()`。本项目的交互不需要这样做。

### 3.3 macOS 打包后

`electron-builder.yml` 已有：

```yaml
mac:
  extendInfo:
    LSUIElement: true
```

`LSUIElement` 是 macOS 应用 `Info.plist` 的配置项，表示应用以 agent 类型运行，不作为普通 Dock 应用展示，仍然可以创建交互窗口。

`app.dock.hide()` 是运行时动作；`LSUIElement` 是打包应用的元数据。项目两者配合，让开发时也能隐藏 Dock，正式包则能从启动阶段就采用相应行为，减少 Dock 图标闪现。

这不是隐藏进程。应用仍可在系统进程管理工具中看到，也需要保留明确的退出入口。

## 4. 第三步：创建托盘图标

先看 **最小教学片段**。在 `app.whenReady()` 之后调用：

```ts
import { app, Menu, nativeImage, Tray } from 'electron'
import trayPath from '../../resources/tray.png?asset'

let tray: Tray | undefined

function createTray(): void {
  const image = nativeImage.createFromPath(trayPath)
  if (image.isEmpty()) throw new Error('托盘图标加载失败')

  tray = new Tray(image)
  tray.setToolTip('JYT Pocket')
  tray.setContextMenu(
    Menu.buildFromTemplate([
      { label: '打开', click: () => mainWindow.show() },
      { type: 'separator' },
      { label: '退出', click: () => app.quit() }
    ])
  )
}
```

这里的 `mainWindow` 指已经创建的 `BrowserWindow`。这段先说明几个对象的职责：

- `nativeImage` 把图片转成 Electron 可用的原生图像对象。
- `Tray` 创建状态栏或系统托盘入口。
- `Menu.buildFromTemplate()` 把菜单配置转成原生菜单。
- `click` 是菜单项被用户点击后的回调。

要让 Tray 对象保持可达，避免被回收。简单示例用模块变量；项目把 Tray 放在 `createResidentWindow()` 的闭包里，并由全局 `resident` 持有返回对象，其方法继续引用 Tray，因此也能保留引用。不是“所有局部变量都必然失效”。

### 4.1 本项目的左右键行为

项目用的是平台分支：

```ts
const menu = Menu.buildFromTemplate([
  { label: '打开 JYT Pocket', click: () => show() },
  { label: '设置', click: () => show('settings') },
  { type: 'separator' },
  { label: '退出 JYT Pocket', click: () => app.quit() }
])

if (process.platform === 'linux') {
  // Linux 桌面环境通常更适合挂接系统托盘菜单。
  tray.setContextMenu(menu)
} else {
  // macOS 和 Windows：右键打开菜单。
  tray.on('right-click', () => tray.popUpContextMenu(menu))
}

// 单击托盘入口呼出窗口。
tray.on('click', () => show())
```

注意：当前**托盘单击是显示，快捷键才是切换**。这两个入口不必做成完全相同的行为。

Linux 托盘表现取决于桌面环境及状态图标支持，不能只凭 macOS 的结果推断所有 Linux 环境都一样。

macOS 的图标使用黑色透明模板图，并配备 2 倍图。具体制作过程在图标篇说明。

## 5. 第四步：先封装可靠的 show

项目节选，`window` 是传给控制器的 `BrowserWindow`：

```ts
const show = (action: WindowAction = 'search'): void => {
  if (window.isDestroyed()) return

  // 用户主动呼出时，撤销之前失焦安排的隐藏。
  cancelAutoHide()
  pendingAction = action

  // 最小化与 hide 不完全相同，因此单独恢复。
  if (window.isMinimized()) window.restore()

  window.show()
  window.focus()
  dispatchAction()
}
```

`show()` 负责可见性，`focus()` 请求输入焦点；聚焦网页里的搜索输入框是另一件事，需要通知渲染进程。

这里出现的三个辅助对象后面会展开：

- `cancelAutoHide()`：取消待执行的失焦隐藏。
- `pendingAction`：记住呼出后要搜索还是打开设置。
- `dispatchAction()`：页面准备好后发送这个动作。

## 6. 第五步：实现显示与隐藏切换

用户要求的是：隐藏时打开，打开时隐藏。项目根据窗口可见状态判断：

```ts
const toggle = (): void => {
  if (window.isDestroyed()) return

  if (!window.isVisible() || window.isMinimized()) {
    show()
  } else {
    // 避免页面稍后加载完成时，还执行之前排队的聚焦动作。
    pendingAction = undefined
    window.hide()
  }
}
```

不能只看 `isFocused()`：窗口可能可见但没有焦点，尤其置顶时更常见。按当前需求，可见状态才是“打开还是收起”的判断依据。

这段逻辑还把最小化视为收起，因此快捷键能把最小化窗口恢复出来。

## 7. 第六步：注册系统全局快捷键

```ts
import { globalShortcut } from 'electron'

const WINDOW_SHORTCUT = 'CommandOrControl+Shift+Space'

// 必须在 app ready 后注册，回调直接复用上面的切换函数。
const registered = globalShortcut.register(WINDOW_SHORTCUT, toggle)

if (!registered) {
  tray.setToolTip('JYT Pocket · 呼出快捷键被占用，请点击图标打开')
}
```

`CommandOrControl` 是 Electron 快捷键表达式：macOS 对应 Command，Windows/Linux 对应 Control。

`globalShortcut` 能在应用未获得焦点时响应。普通网页的 `keydown` 监听做不到这一点。

注册可能失败，例如组合键被其他程序占用或平台限制。返回值必须检查；项目还会在托盘菜单插入不可点击的提示项，用户仍能通过图标进入。

退出时只注销自己注册的组合键：

```ts
if (registered) {
  globalShortcut.unregister(WINDOW_SHORTCUT)
}
```

项目没有使用 `unregisterAll()`，这样后续其他模块注册的快捷键不会被顺带清理。

### 7.1 哪些快捷键其实只是页面快捷键

| 快捷键 | 实现位置 | 未聚焦应用时是否生效 |
| --- | --- | --- |
| Command/Ctrl + Shift + Space | 主进程 `globalShortcut` | 可以，注册成功且平台支持时 |
| Command/Ctrl + K | 页面 `keydown` | 不可以 |
| Command/Ctrl + Shift + N | 页面 `keydown` | 不可以 |
| Esc 收起窗口 | 页面 `keydown` 后调用 preload | 不可以 |

搜索和新增命令是应用内部动作，通常没有必要占用系统全局组合键。

## 8. 第七步：点击其他地方后隐藏

### 8.1 最小实现

```ts
window.on('blur', () => {
  window.hide()
})
```

`blur` 表示**原生窗口失去焦点**。点击另一个应用或桌面，通常会触发这个事件。这里没有监听全屏鼠标，也没有读取其他应用界面。

点击自己页面里的输入框、按钮，通常不会让顶层 BrowserWindow 失焦。不要把它和 DOM 输入框自己的 `blur` 混淆。

### 8.2 为什么不能一直用最小实现

当 `dialog.showOpenDialog()` 打开原生文件选择框时，主窗口也可能失焦。如果立即隐藏主窗口，用户正在选目录的流程就会被干扰。

另外还要处理用户快速切回、窗口已关闭、应用退出、窗口已隐藏、置顶模式。项目因此增加一个短延迟，并在真正隐藏之前重新检查状态。

### 8.3 项目里的失焦隐藏代码

以下变量和函数位于 `createResidentWindow(window)` 的同一个闭包中：

```ts
let quitting = false
let nativeDialogCount = 0
let pendingAction: WindowAction | undefined
let autoHideTimer: ReturnType<typeof setTimeout> | undefined

const cancelAutoHide = (): void => {
  if (autoHideTimer) clearTimeout(autoHideTimer)
  autoHideTimer = undefined
}

const scheduleAutoHide = (): void => {
  cancelAutoHide()

  // 给系统留出短暂的焦点切换时间。
  autoHideTimer = setTimeout(() => {
    autoHideTimer = undefined

    if (
      quitting ||
      window.isDestroyed() ||
      !window.isVisible() ||
      window.isFocused() ||
      window.isAlwaysOnTop() ||
      nativeDialogCount > 0
    ) {
      return
    }

    pendingAction = undefined
    window.hide()
  }, 150)
}

window.on('blur', scheduleAutoHide)
window.on('focus', cancelAutoHide)
```

150 毫秒是本项目的交互选择，不是 Electron 规定的数值。延迟只是为了缓冲焦点变化；真正决定是否隐藏的是回调执行时的状态。

`isAlwaysOnTop()` 的判断同样是产品规则：**本项目置顶后不自动收起**。Electron 不会因为设置置顶就自动帮你禁用 `blur`。

## 9. 第八步：给原生文件对话框加保护

项目用计数器保护整个异步操作：

```ts
const withNativeDialog = async <T>(operation: () => Promise<T>): Promise<T> => {
  nativeDialogCount += 1
  cancelAutoHide()

  try {
    return await operation()
  } finally {
    // 取消选择或抛异常时，也必须释放保护。
    nativeDialogCount -= 1
    if (!quitting && !window.isDestroyed()) scheduleAutoHide()
  }
}
```

调用方式，项目用于选目录、导入与导出：

```ts
const selection = await withNativeDialog(() =>
  dialog.showOpenDialog(window, {
    title: '选择命令的工作目录',
    buttonLabel: '选择此目录',
    properties: ['openDirectory']
  })
)
```

`withNativeDialog` 是自己封装的函数，不是 Electron API。它接受“返回 Promise 的操作”，执行前进入保护，执行后退出保护，原操作的返回类型 `T` 保持不变。

这里必须写 `return await operation()`：需要等异步对话框真正结束再执行 `finally`。直接 `return operation()` 会让 `finally` 提前执行，保护时间就不对了。

计数器比布尔值更能表达重叠操作：只要还有一个原生对话框未结束，计数就大于零。退出保护后重新安排检查，让操作系统有机会把焦点还给主窗口；如果焦点恢复，`focus` 事件会取消隐藏。

这个保护只暂停自动失焦隐藏，不意味着所有收起入口都被锁住。例如快捷键显式调用 `hide()` 是另一条路径。

## 10. 第九步：关闭时收起，退出时真正退出

项目节选：

```ts
window.on('close', (event) => {
  if (quitting) return

  // 普通关闭请求只收起，保留页面与未保存状态。
  event.preventDefault()
  window.hide()
})

const beforeQuit = (): void => {
  // 真正退出时，让后续 close 事件正常关闭窗口。
  quitting = true
  cancelAutoHide()
}

app.on('before-quit', beforeQuit)
```

如果无条件拦截所有 `close`，用户点击托盘“退出”时，`app.quit()` 的关闭过程也可能被阻止。因此需要 `quitting` 标志。

主入口还保留应用进程：

```ts
// 常驻工具不因为没有窗口而主动退出。
app.on('window-all-closed', () => {})
```

正常隐藏并不会触发 `window-all-closed`，因为窗口没有被销毁。这个监听处理的是“所有窗口真的关闭”的生命周期策略。

正常退出路径：

```text
托盘“退出”
  → app.quit()
  → before-quit：允许关闭、请求停止命令
  → 窗口关闭
  → will-quit：注销快捷键、销毁托盘、清定时器
```

不能依赖这些回调处理所有异常断电、系统强杀等场景；需要持久化的数据应在变更时保存，不能全部拖到退出才写。

## 11. 第十步：呼出后聚焦搜索，菜单还能打开设置

原生窗口有焦点，不代表网页里的搜索框已经有焦点。主进程需要发送一个业务动作：

```ts
export type WindowAction = 'search' | 'settings'

let rendererReady = false
let pendingAction: WindowAction | undefined

const dispatchAction = (): void => {
  if (!rendererReady || !pendingAction || window.isDestroyed()) return
  window.webContents.send('pocket:window-action', pendingAction)
  pendingAction = undefined
}
```

为什么不能 `show()` 后立即无条件发送？首次启动时，React 可能还没装好监听器，消息发出也没人接收。

项目采用明确握手：

```text
主进程记住 pendingAction
  → 页面加载
  → 页面先订阅 onWindowAction
  → 页面调用 windowReady()
  → 主进程把 rendererReady 设为 true
  → 发送之前排队的动作
```

返回给主入口的控制对象中有：

```ts
ready: () => {
  rendererReady = true
  dispatchAction()
}
```

完整页面重新加载时需要重新握手：

```ts
window.webContents.on('did-start-navigation', (_event, _url, isInPlace, isMainFrame) => {
  // Hash 路由不重建页面订阅；只处理主页面的真正导航。
  if (isMainFrame && !isInPlace) rendererReady = false
})
```

React 侧的处理集中在 `AppLayout.tsx`：收到 `settings` 调用路由跳转，收到 `search` 调用输入框的 `focus()` 和 `select()`。如果有编辑弹窗或菜单，则保留当前交互焦点。

`pendingAction` 只保存最近一次动作，不是一套消息队列。窗口正在加载时，后来的“打开设置”可以覆盖更早的“聚焦搜索”，符合这个工具的交互需求。

## 12. 第十一步：Esc 收起为什么也要考虑弹窗

前端按键判断的核心是：

```ts
if (event.defaultPrevented || event.isComposing) return

if (event.key === 'Escape' && window.api && !hasOpenOverlay()) {
  event.preventDefault()
  void window.api.hideWindow()
}
```

这是教学节选；项目会继续处理返回结果并 toast 报错。

`hasOpenOverlay()` 检查 dialog、alertdialog、menu、listbox 等浮层。弹窗打开时，Esc 应先交给弹窗；不能用户关掉编辑框的同时整个工具也消失。

`isComposing` 避免干扰输入法组合输入；`defaultPrevented` 尊重其他控件已经处理的事件。

## 13. 第十二步：退出清理

`createResidentWindow()` 返回的 `dispose()` 负责清理自己创建的资源：

```ts
dispose: () => {
  cancelAutoHide()
  window.removeListener('blur', scheduleAutoHide)
  window.removeListener('focus', cancelAutoHide)
  app.removeListener('before-quit', beforeQuit)
  if (registered) globalShortcut.unregister(WINDOW_SHORTCUT)
  tray.destroy()
}
```

主入口连接生命周期：

```ts
app.on('before-quit', () => stopProcesses())
app.on('will-quit', () => resident?.dispose())
```

`stopProcesses()` 是项目自己的子进程清理函数，下一篇会解释；不是 Electron 内置 API。

## 14. 用事件表检查自己的理解

| 用户动作 | 事件或入口 | 当前结果 |
| --- | --- | --- |
| 启动应用 | `whenReady` | 创建隐藏窗口、托盘、快捷键 |
| 单击托盘 | Tray `click` | 显示、聚焦、请求搜索焦点 |
| 右键托盘 | Tray `right-click` | macOS/Windows 打开菜单 |
| 快捷键，窗口隐藏 | `globalShortcut` → `toggle` | 显示 |
| 快捷键，窗口可见 | `globalShortcut` → `toggle` | 隐藏 |
| 点击其他应用 | BrowserWindow `blur` | 延迟检查后隐藏 |
| 正在选文件 | `withNativeDialog` | 暂停自动隐藏 |
| 置顶且失焦 | `isAlwaysOnTop` | 保持可见 |
| 请求关闭窗口 | `close` | 拦截并隐藏 |
| 托盘点击退出 | `app.quit` | 清理资源并退出 |

以上能实现与启动器相似的基础交互。贴近屏幕边缘定位、多屏幕选择、自动调整高度、开机启动等能力不在当前实现里，不能把它们当成已经完成。
