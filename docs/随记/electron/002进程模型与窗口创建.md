# 第 1 篇：Electron 进程模型与窗口创建

## 1. Electron 到底做了什么

普通网页运行在浏览器中，负责显示内容和响应交互。Electron 把 Chromium、Node.js 和桌面系统接口组合起来，让 HTML、CSS、JavaScript 页面可以在原生窗口里运行，并通过受控接口访问文件、托盘和进程等系统能力。

项目中的 React 页面仍然是网页。创建操作系统窗口、注册全局快捷键、执行命令的代码则写在主进程。

```text
Electron 应用
├─ 主进程：应用生命周期、窗口、菜单、文件、外部程序
├─ 渲染进程：Chromium 加载页面，React 在这里运行
│  ├─ preload：页面加载前运行的桥接脚本，处于隔离环境
│  └─ 页面脚本：使用 window.api 调用被允许的能力
└─ Chromium 还会有 GPU 等辅助进程
```

**preload 不是第三个独立进程。** 它是运行在渲染进程中的预加载脚本。项目开启 `contextIsolation` 后，preload 与页面 JavaScript 使用隔离的上下文，通过 `contextBridge` 暴露有限 API。

也不要把 Electron 理解成“一个窗口等于一个 Node.js 进程”。窗口、页面内容和 Chromium 进程由 Electron 管理，学习时先明确代码归属，比记进程数量更重要。

## 2. 为什么要分 main、preload、renderer

| 位置 | 本项目允许它做什么 | 典型代码 |
| --- | --- | --- |
| main | 创建窗口、文件读写、执行命令、系统快捷键 | `new BrowserWindow()`、`spawn()` |
| preload | 包装固定业务接口，收发 IPC | `contextBridge`、`ipcRenderer` |
| renderer | UI、表单、搜索、日志显示 | React、Zustand、`window.api` |
| shared | 类型、校验规则等共享定义 | `PocketAPI`、Zod schema |

例如，页面不能直接写：

```ts
// 反例：不要在 React 页面中引入 Node.js 来执行命令。
import { spawn } from 'node:child_process'
```

本项目明确关闭页面的 Node.js 集成。正确做法是：页面调用 `window.api.executeCommand(id, cwd)`，由主进程决定是否执行。

开启沙箱的 preload 也不能当作完整 Node.js 环境使用；它能使用的模块与能力受到限制。文件读写统一放主进程。

## 3. electron-vite 如何组织工程

项目入口结构如下：

```text
src/
  main/index.ts
  preload/index.ts
  renderer/index.html
  renderer/src/main.tsx
  shared/types.ts
electron.vite.config.ts
electron-builder.yml
package.json
```

编译后，大致对应：

```text
out/
  main/index.js
  preload/index.js
  renderer/index.html
  renderer/assets/...
```

`package.json` 指定 Electron 首先执行哪个文件：

```json
{
  "main": "./out/main/index.js"
}
```

electron-vite 负责开发服务与编译；electron-builder 负责把编译产物及 Electron 运行时组装成应用、安装包。二者分工不同。

项目已存在，不需要重新初始化。学习创建空工程时可以使用 electron-vite 官方初始化流程；具体依赖版本以自己的锁文件为准，不要把教程里某天的版本号当作永久最新版。

## 4. 第一步：创建最小窗口

下面是 **electron-vite 工程内的独立练习入口**，可用于理解 `src/main/index.ts`。它采用普通桌面应用生命周期，后续常驻工具会调整关闭行为。

```ts
import { app, BrowserWindow } from 'electron'
import { join } from 'node:path'

// 保留窗口引用，便于后续判断状态和控制显示。
let mainWindow: BrowserWindow | null = null

function createWindow(): void {
  mainWindow = new BrowserWindow({
    width: 1000,
    height: 700,
    show: false,
    webPreferences: {
      preload: join(__dirname, '../preload/index.js'),
      contextIsolation: true,
      nodeIntegration: false,
      sandbox: true
    }
  })

  // 普通应用可以等页面准备好再显示，减少白屏闪现。
  mainWindow.once('ready-to-show', () => mainWindow?.show())
  mainWindow.on('closed', () => {
    mainWindow = null
  })

  const rendererUrl = process.env['ELECTRON_RENDERER_URL']
  if (import.meta.env.DEV && rendererUrl) {
    // 开发环境连接 Vite 服务，支持页面热更新。
    void mainWindow.loadURL(rendererUrl)
  } else {
    // 打包后加载本地编译产物，用户不需要启动 Vite 服务。
    void mainWindow.loadFile(join(__dirname, '../renderer/index.html'))
  }
}

void app.whenReady().then(() => {
  createWindow()

  // macOS 中应用进程可能仍存在，激活时补建窗口。
  app.on('activate', () => {
    if (BrowserWindow.getAllWindows().length === 0) createWindow()
  })
})

app.on('window-all-closed', () => {
  if (process.platform !== 'darwin') app.quit()
})
```

关键执行顺序是：

```text
app.whenReady()
  → new BrowserWindow()
  → loadURL / loadFile
  → Chromium 加载页面与 preload
  → ready-to-show
  → show()
```

`app.whenReady()` 返回 Promise，表示 Electron 已完成初始化。窗口、托盘、全局快捷键等需要在合适的就绪阶段创建。

`new BrowserWindow()` 创建窗口对象；它不等于“渲染 React”。React 是加载 HTML 后由页面入口启动的。

`__dirname` 在这里对应构建后入口所在目录，所以 preload 路径指向 `../preload/index.js`，不能指向源码里的 `.ts` 文件。

## 5. 第二步：理解窗口常用配置

下面对应项目实际的 `BrowserWindow` 配置。

| 配置 | 本项目值 | 作用 |
| --- | --- | --- |
| `width`、`height` | `1280`、`850` | 初始窗口尺寸，按设备无关尺寸理解，不等同于截图物理像素 |
| `minWidth`、`minHeight` | `720`、`560` | 防止缩小到布局无法使用 |
| `title` | `JYT Pocket` | 初始原生窗口标题 |
| `show` | `false` | 创建后先不显示；常驻版保持隐藏，等用户呼出 |
| `frame` | `false` | 去掉系统窗口边框和标题栏 |
| `skipTaskbar` | `true` | 跳过任务栏显示；macOS Dock 另行处理 |
| `fullscreenable` | `false` | 禁止进入全屏模式 |
| `autoHideMenuBar` | `true` | 自动隐藏窗口菜单栏，主要针对 Windows/Linux |
| `backgroundColor` | `#fafbfc` | 页面绘制前的窗口底色，不负责整个页面主题 |
| `icon` | Linux 时传入 `resources/icon.png` | 指定窗口图标，不能代替所有平台的安装包图标 |
| `webPreferences.preload` | 编译后的 preload 路径 | 页面加载前执行桥接脚本 |
| `webPreferences.contextIsolation` | `true` | 隔离页面与 preload 的 JavaScript 上下文 |
| `webPreferences.nodeIntegration` | `false` | 不给普通页面脚本直接使用 Node.js 的能力 |
| `webPreferences.sandbox` | `true` | 启用渲染进程沙箱，进一步限制渲染环境能力 |

常见但本项目没有在构造器中设置的选项：

| 配置 | 用途 |
| --- | --- |
| `resizable: false` | 固定尺寸的小面板 |
| `alwaysOnTop: true` | 创建时就置顶；项目改用运行时 API 切换 |
| `titleBarStyle` | 保留特定平台标题栏效果的另一种方案 |
| `transparent: true` | 透明窗口，有额外平台限制；本项目不需要 |

不要为了“像原生”一次性加所有选项。当前交互用无框窗口、托盘和焦点事件就能实现。

### 5.1 本项目完整创建参数

项目节选：

```ts
const mainWindow = new BrowserWindow({
  width: 1280,
  height: 850,
  minWidth: 720,
  minHeight: 560,
  title: 'JYT Pocket',
  show: false,
  frame: false,
  skipTaskbar: true,
  fullscreenable: false,
  autoHideMenuBar: true,
  backgroundColor: '#fafbfc',
  ...(process.platform === 'linux' ? { icon } : {}),
  webPreferences: {
    preload: join(__dirname, '../preload/index.js'),
    sandbox: true,
    contextIsolation: true,
    nodeIntegration: false
  }
})
```

这里的 `icon` 来自：

```ts
import icon from '../../resources/icon.png?asset'
```

`?asset` 是 electron-vite 处理资源路径的方式，不是 TypeScript 自带语法。构建工具返回可用于原生 API 的资源路径。

常驻版不再注册“`ready-to-show` 后立刻显示”。否则应用刚启动就会弹出窗口，破坏“启动后只保留托盘图标”的设计。

## 6. 第三步：无边框以后怎样拖动窗口

`frame: false` 去掉系统标题栏后，要在页面中声明可拖动区域：

```tsx
// 渲染进程：Tailwind 任意属性语法。
<header className="[-webkit-app-region:drag]">
  <span>JYT Pocket</span>
  <div className="[-webkit-app-region:no-drag]">
    <input aria-label="搜索命令" />
    <button type="button">设置</button>
  </div>
</header>
```

`drag` 让这一块区域参与原生窗口拖动；`no-drag` 把输入框、按钮等交互区排除出去。忘记 `no-drag` 时，常见表现就是按钮看得见却点不了。

这不是用鼠标事件不断修改窗口坐标，也不需要 React 状态记录每次鼠标移动。

## 7. 第四步：限制页面创建新窗口或跳转

项目节选：

```ts
// 移除窗口菜单；这不是移除 macOS 顶部系统状态栏。
mainWindow.setMenu(null)

// 拒绝页面创建额外的原生窗口。
mainWindow.webContents.setWindowOpenHandler(() => ({ action: 'deny' }))

// 拒绝页面发起的整页导航，保持当前应用页面。
mainWindow.webContents.on('will-navigate', (event) => {
  event.preventDefault()
})
```

`webContents` 可以理解成窗口内的网页内容控制器。控制窗口位置、可见性用 `BrowserWindow`；监听页面加载、发送页面消息等用 `webContents`。

这里不是禁用所有资源请求，也不是阻止主进程自身调用 `loadURL()`。它解决的是页面导航和弹窗边界。

项目使用 `HashRouter`，例如 `index.html#/settings`。切换 hash 不需要服务端返回新页面，适合打包后的本地 `file://` 页面；不要直接照搬依赖服务器重写规则的网页路由部署方式。

## 8. 第五步：区分隐藏、最小化、关闭和退出

| 方法 | 含义 | 当前项目怎么用 |
| --- | --- | --- |
| `window.show()` | 显示现有窗口 | 托盘、快捷键呼出 |
| `window.focus()` | 请求键盘焦点 | 呼出后让用户能输入 |
| `window.hide()` | 隐藏，保留窗口与页面 | 主要收起方式 |
| `window.minimize()` | 交给系统最小化管理 | 不是主要交互 |
| `window.restore()` | 从最小化恢复 | 呼出时防御性处理 |
| `window.close()` | 尝试关闭，触发可取消的 `close` | 当前拦截后改为隐藏 |
| `window.destroy()` | 强制销毁窗口 | 不作为日常收起方式 |
| `app.quit()` | 请求退出整个应用 | 托盘“退出” |

隐藏时不会重新创建 React 页面，所以未保存表单、搜索内容和日志可以保留。它也意味着窗口仍然占用内存，后台任务不会因为界面看不见就自动停止。

事件需要分清：`close` 是“准备关闭”，可以 `preventDefault()`；`closed` 是“已经关闭”，此时不能继续使用旧窗口对象。

## 9. 第六步：避免启动两个实例

项目采用应用级单实例锁：

```ts
// 主进程：应在初始化窗口之前获取锁。
const hasInstanceLock = app.requestSingleInstanceLock()

if (!hasInstanceLock) {
  // 第二个进程退出，系统会通知已有实例。
  app.quit()
} else {
  app.on('second-instance', () => {
    resident?.show()
  })

  app.on('activate', () => {
    resident?.show()
  })

  // 只有取得锁的实例继续创建窗口、托盘和快捷键。
}
```

这里的 `resident` 是项目自己创建的窗口控制对象，下一篇会介绍；不是 Electron 内置全局变量。

单实例锁避免了重复托盘图标、重复注册快捷键、两个进程同时写数据的问题。它不能替代单个进程内部的写入队列。

## 10. 项目的启动顺序

```text
请求单实例锁
  → app.whenReady
  → 设置 Windows 应用标识
  → 根据 userData 路径创建 Repository
  → 读取或初始化数据
  → 创建隐藏窗口
  → 创建常驻控制器：托盘、快捷键、失焦事件
  → 注册 IPC
  → 加载开发网址或打包页面
  → 隐藏 macOS Dock 图标
```

如果数据初始化失败，项目用 `dialog.showErrorBox()` 展示启动错误，再退出，避免悄悄用空数据覆盖坏文件。

`electronApp.setAppUserModelId('com.jyt.pocket')` 来自 `@electron-toolkit/utils`，用于 Windows 应用标识相关处理；`optimizer.watchWindowShortcuts(window)` 也是工具包封装，不是 Electron 原生方法。阅读模板时要把工具函数与官方 API 区分开。
