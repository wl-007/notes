# Python 包管理与环境

## 这部分讲什么

写 Python 时，真正影响开发效率的，往往不是语法，而是环境和依赖管理是否清晰。

这一组文档主要补充 4 个高频工具：

- `uv`：现代化、速度很快，适合新项目
- `conda`：环境隔离和科学计算生态更强，适合数据分析
- `poetry`：偏工程化的依赖管理和打包工具
- `jupyter`：交互式实验、数据探索和教学演示工具

## 学习顺序

如果你是从零开始，建议按下面顺序看：

## 怎么选

### 1. 日常脚本和新项目

优先考虑 `uv`：

- 启动快
- 装包快
- 虚拟环境、依赖、工具运行可以统一管理

### 2. 数据分析和科学计算

优先考虑 `conda`：

- 更适合需要 `numpy`、`pandas`、`jupyter`、`pytorch` 这类生态的场景
- 对非 Python 依赖也更友好

### 3. 需要打包和发布 Python 项目

可以考虑 `poetry`：

- `pyproject.toml` 管理体验完整
- 锁版本、运行命令、构建发布都比较顺手

### 4. 数据探索和教学演示

使用 `jupyter`：

- 适合边写代码边看结果
- 很适合分析 CSV、画图、写实验记录

## 一个简单判断

- 想要更现代、更轻量：用 `uv`
- 想做数据分析、机器学习：用 `conda`
- 想做可发布的 Python 包：用 `poetry`
- 想做交互式分析：用 `jupyter`

## 建议

- 同一项目尽量只选一套主工具链，不要混着管依赖。
- 如果已经用了 `conda` 管环境，就不要再让 `poetry` 或 `uv` 额外接管同一个环境里的全部依赖。
- `jupyter` 只是交互界面，本身不负责完整依赖管理，通常要配合 `uv`、`conda` 或 `poetry` 一起使用。
