Tauri 新增窗口 ​

两种创建窗口的方式 ​

  • Rust 命令方式：前端通过 invoke 调用自定义命令，Rust 端用 WebviewWindowBuilder 创建窗口。
  • JS API 方式：前端直接使用 @tauri-apps/api/webviewWindow 的 WebviewWindow 类创建窗口，不经过自定义命令。

两种方式底层完全一样（JS API 最终也是调用 Rust 的 create_webview_window 命令），区别在于业务逻辑放哪一侧。需要动态计算窗口参数、复用 Rust 生态时选前者；纯前端逻辑、快速原型选后者。

核心概念 ​

  • 窗口标签（label）：每个窗口有全局唯一的字符串标识，创建和查找关闭都靠它。重复创建同标签窗口会报错，所以要先查再建。
  • WebviewWindow：Tauri 里 Window 只是原生壳子，真正渲染页面的是内嵌 Webview，WebviewWindow 把两者打包在一起，是最常用的窗口形态。

Rust 命令方式 ​

rust
use std::sync::Mutex;

use tauri::{AppHandle, Manager, WebviewUrl, WebviewWindowBuilder};

// 防并发锁：异步命令快速连点会并发执行，两个调用都查到窗口不存在、
// 都去 build，第二个就会报 "already exists"。锁把"检查 + 创建"变成原子操作。
static CREATE_LOCK: Mutex<()> = Mutex::new(());

pub fn handle_create(app: AppHandle, payload: Value) -> Result<Value, String> {
    let title = payload
        .get("title")
        .and_then(|v| v.as_str())
        .unwrap_or("置顶窗口");

    let _guard = CREATE_LOCK.lock().unwrap_or_else(|p| p.into_inner());

    // 窗口已存在时直接复用：更新标题并聚焦（get-or-create 模式）。
    if let Some(existing) = app.get_webview_window("demo-always-on-top") {
        existing.set_title(title).map_err(|e| e.to_string())?;
        existing.set_focus().map_err(|e| e.to_string())?;
        return Ok(serde_json::json!({ "ok": true, "reused": true }));
    }

    WebviewWindowBuilder::new(
        &app,
        "demo-always-on-top",                        // 窗口标签
        WebviewUrl::App("index.html".into()),        // 加载的页面
    )
    .title(title)
    .inner_size(400.0, 300.0)    // 内容区域尺寸（逻辑像素，自动适配高分屏）
    .center()                    // 在当前屏幕居中
    .always_on_top(true)         // 置顶，失焦也不会被盖住
    .build()
    .map_err(|e| e.to_string())?;

    Ok(serde_json::json!({ "ok": true, "reused": false }))
}

关闭窗口按标签查找即可：

rust
pub fn handle_close(app: AppHandle) -> Result<Value, String> {
    if let Some(window) = app.get_webview_window("demo-always-on-top") {
        window.close().map_err(|e| e.to_string())?;
        Ok(serde_json::json!({ "ok": true }))
    } else {
        Ok(serde_json::json!({ "ok": false }))
    }
}

命令注册走项目的统一入口 command_rust，在 src-tauri/src/commands/mod.rs 的 match 里加 window:create / window:close 两个任务名。

JS API 方式 ​

前端直接创建，不写任何 Rust 代码：

ts
import { WebviewWindow } from "@tauri-apps/api/webviewWindow";

// 窗口已存在时直接复用（聚焦），不要"先关再建"：
// close() 的 Promise 在发出关闭请求后就 resolve，label 的真正注销
// 要等主线程销毁完成，紧接着创建同样会报 already exists。
const existing = await WebviewWindow.getByLabel("demo-settings-window");
if (existing) {
  await existing.setFocus();
} else {
  // 注意：构造函数本身不会抛出创建失败的错误，
  // 结果通过 tauri://created / tauri://error 两个事件通知。
  const win = new WebviewWindow("demo-settings-window", {
    url: "index.html#/window-settings", // 指向独立路由页面
    title: "示例配置窗口",
    width: 420,
    height: 520,
    center: true,
    alwaysOnTop: true,
  });

  // once 是同步注册的本地监听，不会错过构造函数发出的结果事件。
  void win.once("tauri://created", () => {
    console.log("窗口创建成功");
  });
  void win.once("tauri://error", (event) => {
    console.error("创建失败", event.payload);
  });
}

关闭窗口：

ts
const existing = await WebviewWindow.getByLabel("demo-settings-window");
if (existing) {
  await existing.close();
}

必须授予的权限 ​

core:default 默认权限集不包含创建、关闭和聚焦窗口，需要在 src-tauri/capabilities/default.json 里显式添加，否则 JS API 会报权限错误（例如复用已有窗口时的 setFocus() 报 window.set_focus not allowed）：

json
{
  "permissions": [
    "core:default",
    "opener:default",
    "core:webview:allow-create-webview-window",
    "core:window:allow-close",
    "core:window:allow-set-focus"
  ]
}

Rust 命令方式不需要这些权限，因为命令在 Rust 端执行，不走前端的权限校验。

让新窗口加载指定路由 ​

关键在 url 参数。"index.html#/window-settings" 会被 Rust 端解析成 WebviewUrl::App，再经 URL 拼接得到 <origin>/index.html#/window-settings，hash 路由在新窗口正常生效：

  • 开发环境：http://localhost:14210/index.html#/window-settings
  • 生产环境：tauri://localhost/index.html#/window-settings

配套的前端路由（与主布局平级的顶层路由，新窗口不带底部导航）：

ts
// src/router/index.tsx
export const router = createHashRouter([
  {
    path: "/",
    element: <WorkbenchLayout />,
    children: [
      /* ... 主窗口的全部路由 ... */
    ],
  },
  // 独立配置页：由置顶小窗口加载。
  {
    path: "/window-settings",
    lazy: async () => {
      const { default: WindowSettingsPage } = await import("../pages/WindowSettings");
      return { Component: WindowSettingsPage };
    },
  },
]);

如果配置页不调用任何 Tauri 命令（纯前端 + localStorage），新窗口就无需额外 capabilities。

重复点击报 already exists 是为什么 ​

快速连点"创建窗口"报 a webview with label ... already exists，有两个来源，根子都是同一个：

1. close 后立即重建（最常见）。Window::close() 只是把关闭请求发给主线程事件循环就立即返回，窗口的真正销毁（label 从注册表移除）要等主线程处理 Destroyed 事件后才完成。"先 close 再立即 build 同标签窗口"是经典竞态——build 时旧 label 还占着，直接报错。JS API 的 await win.close() 一样：Promise 在请求发出后就 resolve，不代表销毁完成。

2. 并发创建。异步命令会并发执行，两次点击同时查"窗口是否存在"、都得到否定答案、都去 build，第二个必然撞 label 冲突。

解决方案（上面的代码已采用）：

  • 已存在就复用（set_title + set_focus），不要"先关再建"——从根上消除竞态，体验也更好，这是 Tauri 的 get-or-create 标准模式。
  • Rust 端用 Mutex 把"检查 + 创建"串行化，防住并发双击。

如果业务上必须"关掉重开"（比如要换 url），正确姿势是监听窗口的 Destroyed 事件（app.on_window_event 里的 WindowEvent::Destroyed）确认销毁完成后再创建，或者干脆每次用新的 label。

两种方式对比 ​

维度Rust 命令方式JS API 方式
代码位置Rust 端 commands/window.rs前端页面
需要额外权限否是（create + close + set-focus）
创建结果获取invoke 的返回值 / 错误tauri://created / tauri://error 事件
适合场景窗口逻辑与后端耦合、需要 Rust 能力纯前端控制窗口生命周期
